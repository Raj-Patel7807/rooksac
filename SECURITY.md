# Security policy

## Supported versions

No released or supported engine version exists yet. Security fixes and support expectations will be defined with a future release process.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue until maintainers can assess it. Use the repository’s private reporting mechanism if one is enabled; otherwise contact a project maintainer through the channel documented by the project at that time. Do not include credentials, private keys, or sensitive data in reports.

## Scope

Potential issues may include unsafe parsing, memory-safety defects, dependency risks, build or release integrity, and vulnerabilities in future protocol handling. Reports should include a minimal reproduction, affected revision, impact, and safe mitigation ideas where available.

This policy does not promise a response time or bounty program.
